## 4. 启动验证（实测通过）

`node payload/node/bin/node payload/app/node_modules/@deepseek-ai/dsh/lib/bin.js web --host 127.0.0.1 --port 0`

- **启动输出格式**：`dsh web: http://127.0.0.1:64177 / `（单行，含实际端口）
- **--port 0 解析**：✔ 解析到 OS 分配端口 64177（Rust 侧 parse_port 覆盖 `http://127.0.0.1:` 前缀）
- **进程退出**：SIGTERM 后 code=0 干净退出
- **原生模块**：内置 Node v22.23.2 下 node-pty / sharp 正常加载（GUI 会话是 Node 24，payload 用 Node 22 LTS 无碍）

## 5. 实施中发现的坑（供后续参考）

1. **npm 不回退查找上级 .npmrc**：只在 cwd 找。`payload/app/`、`shell/` 必须各自放 .npmrc（registry + cache），否则回落到不可达的 npmjs 挂死。
2. **`~/.npm` 缓存被 root 污染**（历史遗留，EPERM）：无 sudo 时用项目内独立缓存 `.npm-cache/` 绕开。
3. macOS 上 `node:fs` 的 `rmSync recursive` 偶发 ENOTEMPTY：改用 shell `rm -rf`。
4. `ps`/部分系统命令被沙箱拦截，进程诊断用 `lsof`。

## 6. M1 结论

- 可行。目标网络下 npm 装 `@deepseek-ai/dsh` + `dsh web` 启动链路打通。
- 端口 3080 在本机被占用（会话 GUI），恰好验证了"端口冲突 → --port 0 回退"的必要性。
